From a measurement direction to a result

A browser-only experiment compares two fixed qubit preparations. You can rotate the view, change the measurement direction, and collect individual or 100-trial outcomes. An optional primer and guided challenge connect the interaction to the underlying ideas.

This source-reference route explains the measurement pipeline. No account, API, database, or quantum hardware is involved.

A three-stop route through the code

  1. src/app.mjs · changeAxis sends an actual axis change to setAxis, clears incompatible old results, and redraws the view. Camera dragging has a separate path, so it cannot change the probability model.
  2. src/quantum.mjs · probabilities computes P(+n) = (1 + r·n)/2 for the fixed preparations r = (±1, 0, 0). Z gives equal probabilities; X gives opposite deterministic outcomes.
  3. src/runner.mjs · launch / arrive samples A and B independently. Visible counts change on arrival. Cancellation invalidates queued work, preventing an old flight from adding to a new experiment. src/app.mjs · renderResults displays those counts.

Appearance and words

Layout and labels live in index.html and styles.css. Main explanatory copy is in src/i18n.mjs; it contains English only. The introduction markup is in index.html, with independent interaction state in src/primer.mjs.

Geometry, data, and the guided task

src/geometry.mjs handles the camera and vector projection. src/experiment.mjs holds axis and counts. src/tour.mjs requires actual complete runs for progress and checks exact theoretical discrimination plus actual measurements for the challenge. A lucky histogram cannot pass as proof.

Tests that protect the important distinctions

tests/quantum.test.mjs checks the probabilities. tests/runner.test.mjs checks cancellation and delayed arrivals. tests/flight-ui.test.mjs checks coordinate wiring with a DOM double. tests/tour.test.mjs and tests/tour-ui.test.mjs protect genuine progression and the signed Z readout mapping.

A practice to reuse

Turn a visual promise into a checkable invariant. “Turning the view must not change the experiment” becomes a test that compares probabilities and counts before and after camera motion. The related tests distinguish camera changes from measurement-axis changes and catch regressions without relying on how convincing an animation looks.

Use the same pattern elsewhere: name what must stay unchanged, isolate the state that can change, and test both. Here, event tests complement rather than replace a person trying the rendered app.

Run it again

From the project root, run python -m http.server 8765 --bind 127.0.0.1, then open http://127.0.0.1:8765 on that same machine. Run the tests with node --test tests/*.test.mjs. No dependency installation or build is needed.
